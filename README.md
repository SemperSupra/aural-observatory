# Aural Observatory — native Android C# prototype (v0.6 — BLE + quiet search + Garmin history)

A reproducible, **actual Android app**, authored in C#/.NET 10 for Android, using Android `Activity`/`View` controls and native `AudioTrack` PCM streaming. **There is no WebView, bundled PWA, localhost web service, microphone, Internet permission, telemetry, or cloud account.** A framework-independent `net10.0` core provides signal generation on Windows/macOS/Linux and Android. This repository is open source (MIT).

**Experimental research utility, not a medical device or validated tinnitus treatment.** Generated sound is digitally attenuated but is **not** calibrated in dB SPL; hardware volume, headphone sensitivity, and hearing status affect actual exposure. Start quietly, stop immediately if uncomfortable. Unilateral or pulsatile tinnitus, sudden hearing changes, and other concerning symptoms warrant appropriate professional evaluation. An observation of lower loudness is not a clinical efficacy demonstration.

## Currently implemented

- Two independent ear profiles: perceived frequency (200–10,000 Hz), notch width, digital gain, notch enable, white/pink/brown/blue/violet **approximate** noise.
- Bounded 15-second user-started, nonlooping playback via Android native streaming audio; ramp-in and end fade; STOP and lifecycle cancellation.
- Bounded amplitude modulation (0–20 Hz, depth 0–0.9), seeded pseudorandom generators, transparent config validation.
- Subjective loudness ratings (0–10) before/after a completed listening preview, local CSV observations and explicit Android share sheet export.
- Independent .NET 10 DSP test runner and GitHub Actions Linux Android + Windows/macOS/Linux core build matrix.
- **New optional BLE Heart Rate Service plugin:** shared 0x2A37 parser and portable observation interface, native Android readout/opt-in CSV, Windows and Linux console diagnostic, HR plus RR intervals when the strap actually exposes them, packet quality counters and exploratory RMSSD. Explicit user permission and connect only; no physiological data upload.

Biometric BLE acquisition is now **implemented in source but not yet hardware-qualified**. HRTF, calibrated audiograms, sound-level metering, real-time ECG/EEG/EDA acquisition, notch-equivalence qualification to the previous app, and blinded N-of-1 trials are subsequent, separately gated milestones.

## Build (requires .NET 10 Android workload / Android SDK)

```
dotnet workload install android
dotnet run --project tests/AuralObservatory.Core.Tests/AuralObservatory.Core.Tests.csproj
dotnet build src/AuralObservatory.Android/AuralObservatory.Android.csproj -c Debug
```

Install the debug APK output using `adb install -r <path-to-produced-apk>` after checking the artifact path. Production distribution requires a release keystore, stable application ID, versioning, a privacy policy, reproducible build qualification, accessibility tests, actual device/headphone safety checks, and store review. **Do not publish the test build as a health treatment app.**

Package ID `org.sempersupra.auralobservatory`, min Android API 26. The supported target API is determined by the .NET 10 Android workload (API 36 as of this project). Audio and journaling require no permissions; optional BLE pairing requests Android Bluetooth permissions (or legacy Android 8–11 location permission for BLE scanning).

## Experimental Quiet Search and personal Garmin history (R6)

- **Native Android**: fixed-level logarithmic frequency sweep with touch-hold and Space-key press/release relief reports during/after audio. Explicit system speech dictation captures notes *after* audio; the speech provider may use cloud services despite offline preference. No voice-based automatic DSP control.
- **Windows / macOS / Linux**: `dotnet run --project src/AuralObservatory.SearchDesktop` serves a loopback-only local search UI at `http://127.0.0.1:8766`. Mouse, keyboard Space hold and touch events are handled; 15-second WAV audio is generated by the same C# DSP as Android.
- **Garmin Connect Personal API** (historical-only optional data source): `dotnet run --project src/AuralObservatory.GarminConsole -- Hrv 2026-11-21 <local-output.json>` after supplying `GARMIN_PERSONAL_API_KEY` in a private process environment. Daily HR/HRV/sleep/stress/Body Battery summaries can be read, but **not** used as validated tinnitus biomarkers.
- Neither voice recognition nor personal Garmin imports are required for basic sound playback. No automatic volume increases or unattended changes.
- See `docs/AUTOTUNE-AND-DATASOURCES.md` for limitations, provenance and the remaining multi-dimensional search work.

## Biometrics roadmap

1. **Implemented in source:** standard BLE Heart Rate Service (180D) with optional RR-interval acquisition, native Android and Windows/Linux console connectors; hardware qualification still pending.
2. Offline RR preprocessing with artifact rejection, RMSSD and baseline comparisons. None of these metrics measure tinnitus directly.
3. Optional EDA and EEG adapters behind interface contracts, with open licenses, explicit consent, and timestamp synchronization.
4. Randomized sham/active paired comparisons using the same headphones and session schedule. Primary outcome is user-reported tinnitus burden and residual-inhibition rating, not algorithm-optimized physiology.
5. Hold the generated output steady while sensors observe. Never automatically increase volume based on feedback.

See `docs/HARDWARE-AND-EVIDENCE.md` and `docs/DLE.md`.

- Core code and Android bindings reviewed against the documented .NET/Android APIs.

## Live HRM plugin

The sensor modules target Garmin HRM-Pro Plus or any compliant standard BLE chest strap; the generic 0x2A37 decoder accepts heart-rate-only measurements and optional RR intervals. Follow [docs/SENSORS-BLE.md](docs/SENSORS-BLE.md) for Windows PowerShell 5.1 compatible `dotnet run` commands, Android permission behavior, Mac status, opt-in recording, quality gates and privacy conditions. **Do not buy another strap until Garmin HRM-Pro Plus RR delivery is tested.**

## R7: alternative feedback modes + candidate packages

The Quiet Search now offers hold-when-quiet, hold-while-audible/release-when-quiet (explicitly armed, no default quiet), and tap-to-toggle. Input modes apply to mouse/keyboard/touch or native Android controls, and the R7 journal includes the selected mode in a new file. No change to gain or claim of tinnitus detection.

Public `.github/workflows/package-candidates.yml` requests standard free hosted runners for native Android debug APK, portable Linux/macOS/Windows desktop bundles and an unsigned user-scoped Windows NSIS installer candidate. These are qualification artifacts only, not signed production installers or F-Droid/Play/WinGet releases. Release admission remains with Android Publishing Foundry and Windows Package Foundry and requires explicit owner review; see `docs/QUIET-MODES-AND-PACKAGING-R7.md`.

## R9 desktop and experimental tooling
The portable .NET 10 C# DSP core is shared by Android native AudioTrack and Windows/macOS/Linux desktop local-browser UI; there are no separate platform DSP forks.

Desktop: `dotnet run --project src/AuralObservatory.SearchDesktop` starts a **loopback-only ephemeral-port** server and opens your default browser when a GUI session exists. Use `--no-browser` or `AURAL_NO_BROWSER=1` for test/headless execution; an exclusive per-user data-directory lock prevents multiple concurrent sessions. The in-page **Exit application** button stops the server.

The desktop interface edits independent ear frequencies, notches, noise distributions, gain fractions, and temporal modulation. Save versioned settings to OS user data, create named presets, and restart search to use edited settings. Data/observation journals are retained on upgrades. On Android use user-chosen JSON export/import before uninstall or signing-key changes.

Development gates run on public standard GitHub-hosted Windows 2025, Ubuntu 24.04 and macOS 26 runners. The Chromium+axe suite is synthetic browser automated UX evidence, not manual screen-reader or calibrated acoustic qualification. See `docs/R9-INTEGRATION.md` and `docs/UI-UX-DX-R8-AUDIT.md`.
