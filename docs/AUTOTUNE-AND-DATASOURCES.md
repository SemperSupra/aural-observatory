# Acoustic Quiet Search, voice notes, generic BLE and Garmin history — R6

## Engineering boundary

- **Live sensor** `IPhysiologicalSensor`: BLE SIG 0x180D heart-rate profile, with optional RR-intervals and contact flags. `RequestDeviceAsync` chooses a device on supported platforms and connects to GATT. Discovery/selection is implemented, but persistence/rebonding, real strap pairing, reconnection, and permissions across every OS remain qualification work. Standard Bluetooth does not expose manufacturer-specific ECG automatically.
- **Historical health data** `IHistoricalDataSource`: Garmin Connect Personal API read-only snapshots from the user's personally issued key, never live HR or beat timing. Supports heart rate, HRV, sleep, stress, Body Battery and daily summaries. Does **not** insert observation data automatically into experiments. Explicit local per-date import only. `GarminPersonalSource` is reference C# implementation using official endpoints; synthetic HTTP tests verify requests, not Garmin credentials or live account access.
- **Human input**: quiet hold intervals, before/after loudness, optional text or explicit system speech dictation; these are subjective observations and cannot prove efficacy.
- **Search controller**: `QuietSearch` deterministic randomized logarithmic frequency trials, repeated baseline control, 15s fixed-volume auditory preview, >=10s after-sound observation, zero automatic output gain changes, optional refinement near an exploratory high-scoring candidate.

## Research and safety constraints

1. Quiet *during playback* may be masking. Quiet *after stopping* may be residual inhibition. These are stored separately. The app does not diagnose clinical tinnitus improvement or identify an objective neurological silence state.
2. No optimizer may increase device SPL or gain, bypass output limits, automatically change headphone route, use another person's data, or continue without explicit user action.
3. The fixed digital ceiling does not define headphone sound-pressure level. Acoustic-device qualification, comfortable user-set volume, and stopping on discomfort remain mandatory.
4. The initial objective is exploratory per-user ranking (post-stimulus holds); avoid strong inference from one session, require repeats and varied days, randomized sham/active designs before any effectiveness assertions.
5. Record experiment ID, algorithm version, transform settings, random seed, actual playback completion, both quiet-hold windows, post-ratings, and interruptions. Existing base sensor data uses host receipt timestamps rather than sensor-side ECG timing.
6. Historical Garmin data and credentials stay local and are not uploaded to the public/private repositories. If a user exports medical data, it is a deliberate sensitive-data operation.

## Android native implementation

The on-device UI has `START / NEXT SEARCH TRIAL`, touch/pointer hold `PRESS AND HOLD WHEN QUIET`, physical Space-key down/up support, notes, and `DICTATE` via the user's installed system speech recognizer. The speech intent sets `EXTRA_PREFER_OFFLINE`, but the system speech provider might still use a network service. Dictation is only invoked explicitly **after playback** and is annotation-only; no speech command may increase volume or directly change DSP during a trial.

## Desktop implementation

`dotnet run --project src/AuralObservatory.SearchDesktop` starts a loopback-only ASP.NET Core server at http://127.0.0.1:8766. Its minimal browser UI accepts mouse press/release, keyboard Space down/up, and touch pointer events. Audio samples are generated by the same C# `StimulusEngine` as Android, encoded as bounded 16-bit WAV. The web page does NOT implement a separate DSP engine. Loopback endpoints require a randomly generated per-process token. The browser's playback completion event is an approximate endpoint time; qualify actual device latency.

## Garmin Personal API qualification

Official docs: https://developer.garmin.com/gc-developer-program/personal/personal-api/
Reference source: https://github.com/garmin/connect-personal-api-python

The user alone creates a personal key in Garmin Connect. Desktop console uses the `GARMIN_PERSONAL_API_KEY` environment variable, exchanges it for a bearer token over TLS, then retrieves exactly one user-requested dataset/date and writes only to a caller-chosen local JSON path. No automatic Garmin access occurs, including during sound experiments. Never log, commit, share, or persist API keys, tokens, or raw physiological observations. Tokens are not cached in this initial integration.

Run example:

```powershell
# Use a user-controlled secure environment, not checked-in source or shell history.
dotnet run --project src/AuralObservatory.GarminConsole -- Hrv 2026-11-21 "$env:LOCALAPPDATA\AuralObservatory\garmin-hrv.json"
```

This is designed for **individual personal use only**. Garmin's Personal API is not the OAuth solution for a public multiuser app; retain its adapter as an optional user-supplied private local data source.

## Further qualification gates

- **Q1:** synthetic C# search and Garmin HTTP tests green on Windows/macOS/Linux; Android compilation green.
- **Q2:** real BLE Garmin HRM-Pro Plus discovery/pairing, GATT RR flag observation, reconnection, disconnection, app lifecycle, and permission testing on each platform.
- **Q3:** true human press/hold timing on desktop and Android; mixed pointer/key, lost-focus, accessibility, pause/stop behavior, loudness recording and crash recovery.
- **Q4:** Garmin API user-issued key test, account-scoped access restrictions, response schemas for all datasets, token revocation/errors, no log leakage.
- **Q5:** real Android device acoustic measurements and headphones; user consent, privacy disclosure and bounded trial protocol.
- **Q6:** richer multi-axis (noise color, notch width, AM, spatial/temporal graphs) constrained Bayesian/bandit optimizer with exploration quota and sham controls. No acoustic intensity optimization.
- **Q7:** opt-in continuous on-device voice/desktop STT provider qualification; distinguish vendor online services from verifiably offline open-source engines (Vosk/whisper.cpp) and pause audio while listening to avoid feedback contamination.
