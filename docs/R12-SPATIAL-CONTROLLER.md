# R12 — virtual spatial sound controller and optional physical gamepad

Status: **experimental, unscored, desktop-only draft**. Governing [Aural DLE #5](https://github.com/SemperSupra/aural-observatory/issues/5); adopted canonical Way of Working and original study constraints remain authoritative.

## User controls

The desktop Quiet Search UI now contains optional **twin on-screen analog pads**: a top-view sound-direction pad around a head and a second pad for elevation/distance, plus accessible azimuth (−180° to +180°), elevation (−45° to +45°), and relative distance (1–3×) sliders. Both pads support pointer, touch and arrow keys; Home or X/Center returns to the reference position. Virtual face buttons A/Mark, B/STOP, X/Center and Y/Play-prepared are explicit human controls. Y only forwards the already prepared manual preview's Play control; it cannot create a signal or start an experiment. Escape requests STOP. Enabling 3D sound is an explicit click and **does not start playback**. The existing manual-sweep button remains the only way to prepare a signal; the existing Play prepared control and the virtual Y button can start an already prepared manual preview from a deliberate click. These controls do not alter a randomized trial, change saved clinical observations or start sound in response to stick movement.

Only `manual-mode=ReferenceTone` and `manual-ear=Both` may enable the spatial adapter; selecting an isolated ear or moving-notch noise disables it. The source signal is still generated and digitally bounded by the **existing C# `StimulusEngine`** and delivered as an authenticated local WAV Blob. The platform's `AudioContext` /`PannerNode` `HRTF` spatializes that signal as a *post-render listening adapter*, with a fixed output gain of **0.25**, inverse distance attenuation and parameter smoothing. That is **additional digital attenuation, not calibrated sound-pressure exposure**. A stereo reference tone may be downmixed for a single perceived spatial source; left/right noise and notch study isolation is intentionally never passed through this panner. The randomized `#sound` audio element, quiet-score journal, and experiment state machine remain untouched. Neither automatic correction of device output volume nor any medical benefit is claimed.

## Physical controller

The UI opt-in polls standard browser `navigator.getGamepads()` on animation frames. It lists device identity/mapping, accepts user-selected axis/button indices (0–7 / 0–17), applies an analog deadzone and bounded rate control, and supports ordinary Xbox-compatible browser mappings as the initial default. The optional mapping also allows a **Logitech Rumblepad 2** or another legacy HID/DirectInput device **if and only if the OS/browser exposes it**. No particular vintage device is claimed hardware-qualified. If it is not enumerated, use the virtual pad/keyboard or later native platform bridge. Unsupported hardware is never permitted to bypass an OS gesture/permission or invent a host event.

Default mapping: left X axis yaw, left Y elevation, right Y distance, A button mark (only while a manual tone is playing), B button STOP, X button center. A trigger/axis NEVER starts playback. Physical START is intentionally not mapped: Gamepad polling does not consistently satisfy browser user-activation requirements and unattended audio would violate the adopted consent boundary. Manual Start and prepared Play remain accessible as actual user controls. The HTML is accessible without gamepad support and at 320px. All controls and labels operate in light/dark/high-contrast/reduced-motion schemes inherited from R9.

## Hard gates and qualification

The app must not be described as measuring sound location or producing HRTF localization equivalent across ears. Spatial accuracy depends on the browser, HRTF profile, headphones and individual hearing. A browser STOP pauses/releases the current local media element and calls the existing token-authenticated loopback `sweep-stop` API, but **does not verify physical hardware output buffers, SPL or actual silence**. Real USB Logitech Rumblepad 2/Xbox devices, controller mappings on Windows/Android/macOS, native gamepad permission, host-gated physical STOP, HRTF ear-isolation acoustics, accessible manual assistive-technology use and calibrated exposure all remain HOLD for later qualification.

Qualify via existing `.github/workflows/desktop-browser-ci.yml`: genuine Chromium + Playwright + axe, original C# desktop host, token-authenticated bounded WAV, virtual pad and keyboard, positive/negative HRTF opt-in, synthetic browser Gamepad API fixture, STOP, no autoplay, randomized-trial isolation and a saved screenshot artifact. A synthetic Gamepad browser object is **not** a claim to have connected the user's real controller. Keep this draft stacked on existing R10 [desktop sweep PR #24](https://github.com/SemperSupra/aural-observatory/pull/24); do not bypass R9/R10 owner review or merge/release without authorization.
