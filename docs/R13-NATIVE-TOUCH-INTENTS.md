# R13-N — native .NET/Android touch-intent workcell

**Purpose:** prepare a no-device, input-only primitive for the *existing native* Android app in the Aural Observatory project. Source references: [Aural DLE #5](https://github.com/SemperSupra/aural-observatory/issues/5), native R10 Android [#23](https://github.com/SemperSupra/aural-observatory/pull/23), R12 browser spatial manual preview [#29](https://github.com/SemperSupra/aural-observatory/pull/29), and R13 Open Space Duel contextual mobile overlay [#30](https://github.com/SemperSupra/aural-observatory/pull/30).

This PR is deliberately independent from the HTML/WebAudio branch. The Android app uses **native C# Views/AudioTrack, not a WebView**; the desktop preview's CSS/JS cannot be deployed inside it without a prohibited architectural shortcut.

The new pure `AuralObservatory.Core.SpatialTouchIntentProjector` accepts one tracked pointer ID per zone with floating origin, radius proportional to the native view bounds, 14% radial deadzone, bounded head-relative azimuth, elevation and relative distance, stale/wrong pointer rejection and exact cancellation on Android `ACTION_CANCEL`, rotation and Activity Pause. State is an immutable `SpatialTouchSnapshot` for a native View binding. It **never** generates or starts audio, allocates an `AudioTrack`, changes gain, claims an HRTF sound route, writes a journal or handles any sensor/microphone data.

The dedicated public 3-OS `.NET 10` CI executes more than six thousand deterministic adversarial assertions (simultaneous fingers, cancellation independence, stale IDs, invalid dimensions/NaNs, deadzone, extreme coordinates, reset). **Now implemented as an input-only native UI candidate:** `src/AuralObservatory.Android/NativeSpatialTouchSurface.cs` draws independent native Android left/right touch zones and handles actual `MotionEvent` pointer-down/move/up/cancel with two tracked pointer IDs. `MainActivity` adds an explicit 'OPEN NATIVE SPATIAL TOUCH CONTROLS (INPUT ONLY)' action in the existing sound panel; the native dialog has STOP AUDIO, CLOSE + STOP, status and CENTER controls. `OnPause` cancels both pointers, dismisses the dialog and stops the existing AudioTrack. **The coordinates are not attached to AudioTrack/HRTF; the UI is a truthful input demonstration, not audible spatial movement.** The project is compiled by the existing native Android CI workflow, but no real-device/touch/HRTF or acoustic qualification has occurred. Code review and real-device functional tests are required before routing position to a qualified native HRTF/spatial DSP.

**Known non-equivalence:** browser coordinates are CSS pixels; Android receives device-scaled view coordinates. The percentage radius/deadzone mapping and semantic bounds are purposefully aligned, but touch-vs-physical-size, gesture ergonomics, per-ear HRTF, screen readers, tablet split-screen, rotation, gesture navigation and actual hardware remain **UNKNOWN**. No Aural audio study data or physical headphones are accessed; no release, signing, merge or native HIL authority is gained from synthetic CI.

Accept as a *native input prototype and compilable view*, not a completed audible Android spatial controller. Android TalkBack/manual screenreader evaluation, split-screen/rotation, device-stop performance and native HRTF remain owner gates. Governed by canonical Way of Working, root AGENTS, DLE #5 and explicit workcell source ownership.
